# Theme knobs

A brand is a handful of knobs. Everything else (semantic colours, component radii, type) is derived from them, so a new brand never touches a component.

| Knob | Tokens | What derives from it |
| --- | --- | --- |
| **Primary colour** | `theme.color.primary` → `color.primary.50–950` | Primary buttons, focus ring, selected controls, links |
| **Secondary colour** | `theme.color.secondary` → `color.secondary.50–950` | Secondary buttons and badges, secondary emphasis |
| **Highlight colour** | `theme.color.highlight` → `color.highlight.50–950` | Highlight badges, markers, progress and chart emphasis (`color.emphasis.highlight.*`, Tailwind `bg-highlight`, `bg-highlight-subtle`…) |
| **Neutrals** | `color.neutral.*` | Backgrounds, surfaces, text, borders |
| **Radius** | `theme.radius` | `radius.surface` (×1), `radius.control` (×0.75), `radius.inner` (×0.5) |
| **Font** | `theme.font.body`, `theme.font.display`, `theme.font.mono` | Body text, titles (`font-display`), code |

The knobs live in `packages/tokens/src/brand/<name>.json`.

## From one colour to a scale

Each seed colour becomes an 11-step scale (`packages/tokens/palette.ts`). Steps are placed by **OKLCH lightness**, which tracks how light a colour looks across hues, so a given step has about the same contrast whatever colour you pick: step 600 always carries white text, step 400 always carries near-black text. The seed sets the hue and colourfulness. The token build checks every text/background pair against WCAG AA in both modes, and the examples below use the same generator.

## Brand and mode are separate

Light and dark are a **mode** (`data-theme`); a **brand** (`data-brand`) sets the knobs. Any brand works in either mode: switch the toolbar theme to see the examples in both. Setting `data-brand` on any element re-derives the tokens for its subtree, which is how each example themes itself without touching the rest of the page.

## Try it in the web app

The interactive playground (three colour pickers, the radius and the font, over a gallery of components) lives in the web app, where your knobs survive light/dark switches and reloads and can be shared as a link. Run `pnpm dev` and choose **Theme knobs** in the header (`#/theme-knobs`).
